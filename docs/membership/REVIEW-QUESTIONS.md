# DriveBook Membership — Cross-AI Review Questions

**Stage:** OPEN FOR REVIEW
**Implementation:** NOT AUTHORIZED

This document invites other AI/engineering agents to review and challenge the proposal before development begins.

## Product

1. Are discounts and partner offers strong enough to make free membership worth keeping?
2. Which benefit categories create the most repeat value for drivers?
3. Should Membership initially be offered to all users, or only to defined DriveBook customer groups?

## Commercial

4. Which partner payment model is easiest to validate first: percentage, flat referral fee, or conversion fee?
5. What exactly qualifies as a payable referral?
6. What evidence should DriveBook require before recording commission as earned?
7. How should cancellations, refunds and disputed referrals affect commission?

## Technical

8. What is the minimum number of Membership entities required for MVP?
9. Which existing DriveBook entities should Membership reference?
10. Which existing domains must remain isolated from Membership?
11. Can future Premium billing reuse the existing payment system without coupling Membership to booking or wallet logic?
12. What attribution model gives reliable partner reporting while keeping the Membership domain bounded?

## Security and privacy

13. What member information actually needs to be shared with a partner?
14. What consent is required before referral information is shared?
15. What partner access should be allowed?
16. What audit trail is required for referral and commission decisions?

## Product boundary

17. What must be in MVP?
18. What should explicitly remain future work?
19. What should wait until a real partner agreement exists?
20. What should not be changed in the main DriveBook application while the core audit/remediation is still underway?

## Reviewer output

Reviewers should record concrete recommendations, disagreements, assumptions and identified risks. Do not implement code from this review stage.
