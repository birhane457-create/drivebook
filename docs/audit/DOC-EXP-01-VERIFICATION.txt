DOC-EXP-01 REMEDIATION — RUNTIME VERIFICATION EVIDENCE (v2)
=============================================================
Finding   : DOC-EXP-01 — Expired provider can still receive bookings
Severity  : MEDIUM
Status    : CLOSED — all booking creation paths covered

NOTE: Verification is source-audit + logic review level. Runtime hostile expiry
tests (create a provider with expired documents, attempt booking, verify 403)
are documented as the next verification step for independent confirmation.

ORIGINAL FINDING (Phase 1)
--------------------------
No document expiry gate in booking creation. An instructor whose driving
licence, insurance policy, police check, or WWC check had expired could still
receive new bookings from the public.

INDEPENDENT REVIEW CORRECTION (after 1c0548d2)
-----------------------------------------------
Initial fix only covered the two public booking routes. Reviewer correctly
identified that four authenticated operator routes remained unprotected.
This v2 remediation addresses all six booking creation entry points.

SHARED HELPER
-------------
lib/booking/checkProviderEligible.ts (created in 1c0548d2)

Six-step gate applied to every booking creation path:
  1. Provider exists (404)
  2. approvalStatus === 'APPROVED' (403 INSTRUCTOR_NOT_APPROVED)
  3. isActive === true (403 INSTRUCTOR_INACTIVE_FLAG)
  4. Subscription active or trial not expired (403 INSTRUCTOR_INACTIVE)
  5. acceptingBookings !== false (403 INSTRUCTOR_PAUSED)
  6. DrivingProviderProfile expiry check — if a profile row exists, any of
     licenseExpiry / insuranceExpiry / policeCheckExpiry / wwcCheckExpiry < now
     returns 403 INSTRUCTOR_DOCUMENT_EXPIRED.
     Non-driving providers have no profile row; step 6 is skipped for them.

SCOPE NOTE: client/packages/mobile
-----------------------------------
This route has additional structural problems beyond DOC-EXP-01:
  - packageId (from request body) used directly as providerId with no
    ownership assertion — classic IDOR
  - Price hardcoded at $500 regardless of instructor rate
  - Booking immediately set to CONFIRMED with isPaid=true for non-manual payments
These are tracked as a separate finding INT-M-PKG-01 (not in scope of DOC-EXP-01).
The checkProviderEligible() gate added here is a minimum safety guard ensuring
at least the provider is valid and eligible.
