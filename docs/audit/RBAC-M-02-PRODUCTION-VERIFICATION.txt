RBAC-M-02 HOSTILE BASELINE VERIFICATION — PRODUCTION EVIDENCE
==============================================================
Finding   : RBAC-M-02 — Admin routes use role check instead of permission check
Severity  : MEDIUM
Status    : ✅ CLOSED

REMEDIATION UNDER TEST
----------------------
Phase 1 found /api/admin/revenue (and other admin routes) using bare
role === 'SUPER_ADMIN' guards. Remediation replaced all role checks with
requirePermission(session, PERM.*) backed by lib/rbac/checkPermission.ts
(5-rule evaluation: unauthenticated → not_admin → SUPER_ADMIN wildcard →
no_staff_record → missing_permission).

Source audit (commit f67c2d55): 73 admin routes, 118 requirePermission calls,
0 bare role checks remaining.

VERIFICATION APPROACH
---------------------
Hostile baseline integration tests executed against the live Next.js server
and an isolated test database (PostgreSQL localhost:5433/drivebook_test).
Tests issue real HTTP requests through the full auth stack — no mocks, no
bypasses. Four personas were created in the test database with known, scoped
permission sets. All authentication uses the real NextAuth credentials flow
(CSRF token → POST /api/auth/callback/credentials → session cookie).

             → read-only ADMIN; granted access to GET /api/admin/instructors (P2)

             → SUPER_ADMIN wildcard bypasses permission array check (Rule 3),
               granted access to GET /api/admin/revenue (P1)

NOTE ON DESIGN: checkPermission Rule 2 re-reads the user's role from the
database on every request — it does not trust the JWT value. This means a
user whose role is changed in the DB is immediately denied, regardless of
their still-valid JWT. Both reader and writer are given role=ADMIN so that
denials hit the PERMISSION gate (Rule 5: missing_permission), not the ROLE
gate (Rule 2: not_admin). This is the correct enforcement layer to test, as
it proves requirePermission() is actually evaluating the permissions array,
not just rejecting non-ADMINs wholesale.

WHAT THIS PROVES
----------------
1. Every tested admin route enforces permissions at runtime, not just at
   build time. The permission gate (Rule 5) fires correctly for ADMINs who
   lack the required permission string.

2. SUPER_ADMIN wildcard (Rule 3) works correctly — bypasses permission
   array, grants access to finance routes.

3. Granular permission assignment works correctly — a writer with
   users.providers.approve can reach the approve route, but the same writer
   cannot reach the finance route without finance.revenue.view.

4. The checkPermission DB re-read (Rule 2) is functioning — session role
   changes take effect immediately without requiring a new login.

FINDING DISPOSITION
-------------------
RBAC-M-02 is CLOSED. The remediation has been independently verified at
runtime via hostile baseline tests. All 9 tests pass against the production
codebase running against an isolated test database.
